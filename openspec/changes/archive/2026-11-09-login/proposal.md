# Proposal

## Why

Приложением хотят пользоваться друзья, но сейчас база общая: все видят одни и те
же контакты. Нужно, чтобы каждый заходил под своей почтой, вёл свои контакты и не
видел чужие. Вход — по ссылке из письма, без паролей.

## What Changes

- Появляется вход по ссылке из письма (magic link): ввёл почту → пришло письмо →
  открыл ссылку → внутри. Паролей нет. Первый вход и есть регистрация, имя не
  спрашиваем.
- Появляется страница входа: поле почты и кнопка «Получить ссылку». Без входа
  приложение не открывается.
- В шапке появляются почта вошедшего и кнопка «Выйти» (выход только на этом
  устройстве).
- У каждого контакта и группы появляется владелец; заметки принадлежат владельцу
  контакта. Пользователь видит и меняет только своё — в списке, поиске, карточке,
  заметках, группах, фильтре по группе и блоке «Пора связаться». Чужое не
  открывается ни в интерфейсе, ни прямым запросом к серверу.
- **BREAKING** Группы теперь принадлежат владельцу: название группы уникально
  только внутри одного пользователя, а не на всю базу. У A и B может быть по
  своей группе «Друзья».
- Письма отправляются одной библиотекой (Nodemailer): локально и в автотестах —
  в почтовую заглушку Mailpit, на сервере — через Resend. Куда слать, решают
  настройки окружения, а не код: одна и та же сборка работает и локально, и на
  сервере.
- Разовая миграция делает все уже существующие контакты, заметки и группы, а
  также демо-данные, собственностью одного пользователя — владельца, чья почта
  задаётся настройкой `OWNER_EMAIL`. Ни одна запись не теряется.
- Автотест входа (e2e) проверяет изоляцию двух пользователей A и B. Автотест
  главного сценария остаётся отдельным, но теперь сначала входит под
  пользователем (без входа приложение закрыто).

Намеренно вне объёма этой фичи (из раздела «Не делать» требований):

- Пароли, вход через Google и соцсети, вход по коду из письма, профиль и смена
  почты, удаление аккаунта, общий доступ к контактам, приглашения, роли и
  админка.

## Capabilities

### New Capabilities

- `user-auth`: вход по ссылке из письма (magic link), отправка и доставка письма
  (Mailpit/Resend через Nodemailer, выбор настройкой), срок и одноразовость
  ссылки, лимит писем, сессии и выход, серверная проверка почты и неразглашение
  существования пользователя, изоляция данных по владельцу (каждый видит и меняет
  только своё), а также разовый перенос уже существующих данных на владельца.

### Modified Capabilities

- `contact-groups`: уникальность названия группы становится не глобальной, а в
  пределах одного владельца (A и B могут иметь одноимённые группы). Создание,
  назначение, фильтр, переименование и удаление теперь работают в границах
  данных текущего пользователя.

## Impact

- **База данных (Drizzle):** новые таблицы Better Auth (`user`, `session`,
  `account`, `verification`); колонка-владелец `owner_id` у `contacts` и `groups`
  (заметки и связи групп наследуют владельца через свой контакт/группу);
  функциональный уникальный индекс групп переезжает с «имя» на «владелец + имя».
  Миграция в три шага: добавить `owner_id` (nullable) → создать пользователя
  `OWNER_EMAIL` и проставить владельца всем существующим записям → сделать
  `owner_id` обязательным.
- **Новые зависимости:** `better-auth` (вход и сессии), `nodemailer` (отправка
  писем, в т.ч. через SMTP Resend), `@types/nodemailer`. Все совместимы с текущим
  стеком (Next 16, React 19, drizzle-orm 0.45, drizzle-kit 0.31).
- **Серверный код:** конфигурация Better Auth и его маршрут; серверный модуль
  отправки письма через Nodemailer; все серверные действия и запросы страниц
  (`src/app/actions.ts`, `src/app/page.tsx`, `src/app/contacts/[id]/page.tsx`,
  `src/app/groups/page.tsx`, `src/lib/keep-in-touch.ts`) начинают фильтровать и
  записывать по текущему пользователю и отвергать доступ к чужим записям.
- **Интерфейс:** страница входа, страницы-ответы «ссылка отправлена» и «ссылка
  устарела», почта и кнопка «Выйти» в шапке (`src/app/layout.tsx`), пустой список
  с подсказкой «Добавь первый контакт» для нового пользователя.
- **Инфраструктура:** Mailpit добавляется в локальный `docker-compose.yml` и в
  e2e-окружение CI; переменные окружения для Better Auth, SMTP и `OWNER_EMAIL`
  добавляются в `.env.example` и `deploy/.env.example`; на сервере задаётся ключ
  Resend и домен отправителя `mail.crm.<домен>`.
- **Выкатка:** перенос существующих данных выполняется шагом миграции до старта
  нового образа; откат — только вместе (база из бэкапа до выкатки + прошлая
  версия приложения), как указано в требованиях.
- **Демо-данные (`src/db/seed.ts`):** создаются у пользователя `OWNER_EMAIL`.
